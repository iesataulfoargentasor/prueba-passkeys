Acceso con passkeys desde el móvil

Objetivo: crear una cuenta, asociarle una passkey y volver a entrar con la verificación del dispositivo. Es una demostración de autenticación real con Clerk, sin escribir un servidor propio. Necesita una aplicación de Clerk configurada por el docente.

1. Qué necesitas

  • Un móvil compatible con passkeys, bloqueo de pantalla configurado y un navegador actualizado. Para probar específicamente la huella, el móvil debe tener sensor y una huella registrada.
  • Una cuenta de Clerk y un correo de pruebas que puedas verificar.
  • Un alojamiento HTTPS para abrir la aplicación desde el móvil.

La huella, el rostro o el PIN autorizan al dispositivo a usar la credencial. La web no puede obligar a utilizar exclusivamente la huella ni recibe la imagen biométrica. WebAuthn necesita un contexto seguro. Referencia de WebAuthn.

Esta práctica introduce eventos, promesas y async/await. Es una ampliación guiada, no un ejemplo limitado a la UT4. Para localizar elementos se utiliza únicamente document.getElementById().

2. Configurar Clerk

  1. Entra en Clerk Dashboard y crea una aplicación, por ejemplo Aula DWEC Passkeys.
  2. Mantén seleccionada la instancia Development. En User & authentication, habilita el correo con código de verificación para el registro y el acceso inicial. Deja este método disponible para recuperar el acceso.
  3. En Passkeys, activa Sign-in with passkey y guarda. Los nombres del panel pueden variar ligeramente.
  4. En API keys, copia la Publishable Key de desarrollo y el dominio de Frontend API URL. Si no ves el dominio por separado, selecciona JavaScript en Quick Copy: aparece en las direcciones de los scripts.
  5. Abre config.js y sustituye los dos textos de ejemplo. La clave comienza por pk_test_. El dominio tendrá una forma similar a tu-instancia.clerk.accounts.dev: copia el tuyo, sin https:// ni barra final.

La clave publicable está pensada para el navegador. Nunca copies una Secret Key (sk_...) en estos archivos.

Clerk requiere un registro previo mediante otro método antes de añadir una passkey. Su documentación permite probar esta función en desarrollo; para producción requiere un plan de pago. Consulta las condiciones antes de convertir la práctica en un servicio real. Configuración oficial.

3. Abrir la práctica en el móvil

Para esta prueba puedes alojar los archivos estáticos en GitHub Pages. El alojamiento de la web y la instancia de desarrollo de Clerk son servicios distintos.

  1. Crea un repositorio independiente, por ejemplo prueba-passkeys. Si utilizas GitHub Free, usa un repositorio público para Pages.
  2. Sube el contenido de esta carpeta: index.html, styles.css, config.js, app.js y LEEME.html. Deben quedar en la raíz, sin una carpeta adicional envolviéndolos.
  3. En Settings → Pages, selecciona publicación desde una rama, main y /(root). Guarda y espera a que termine la publicación.
  4. Abre la dirección que muestre Pages, similar a https://TU_USUARIO.github.io/prueba-passkeys/, directamente en el navegador del móvil.

Instrucciones oficiales de GitHub Pages.

Para revisar en el ordenador puedes servir la carpeta con Live Server de VS Code y abrir http://localhost:5500. No abras el HTML mediante doble clic. Una dirección como http://192.168.1.20:5500 desde el móvil no proporciona el contexto seguro necesario.

Crea y usa la passkey en la misma dirección de la práctica. Una credencial creada en localhost o en el portal de cuentas de Clerk no sirve automáticamente en otro dominio. El ejemplo abre los formularios y el perfil dentro de la aplicación para mantener el dominio. Dominios y passkeys en Clerk.

4. Prueba completa, paso a paso

  1. En el móvil, pulsa Crear cuenta, introduce un correo de pruebas y completa el código recibido. Usa un nombre ficticio si el formulario solicita un nombre.
  2. Comprueba que la pantalla muestra la sesión iniciada y tu cuenta.
  3. Pulsa Crear mi passkey. Sigue el diálogo del sistema y guarda la credencial en el gestor que te ofrezca el móvil. Autoriza con huella, rostro o PIN.
  4. Espera el mensaje de confirmación. Si cancelas, la página permite repetir la operación.
  5. Pulsa Cerrar sesión. Comprueba que reaparecen los botones de acceso y registro.
  6. Pulsa Iniciar sesión y elige Sign in with a passkey o la opción equivalente del formulario. Según la interfaz, puede aparecer entre otros métodos de acceso.
  7. Selecciona la credencial y verifica tu identidad con el móvil. Al completar el acceso, volverás a la aplicación.
  8. En Gestionar mi cuenta, revisa la sección de seguridad y las passkeys. Puedes eliminarlas al terminar la práctica; si el gestor del móvil conserva una entrada, elimínala también desde ese gestor.

Los formularios de Clerk pueden aparecer en inglés. Las etiquetas de nuestra aplicación están en español. Que una sesión se restaure al recargar no demuestra una nueva verificación biométrica: cierra sesión antes de repetir el paso 6.

5. Cómo explicar el código en clase

HTML: define dos zonas, con sesión y sin sesión, y los botones. CSS: adapta la presentación al móvil. config.js: identifica la instancia. app.js: conecta los botones con Clerk y actualiza la pantalla.

  1. cargarScript() carga las bibliotecas. Se puede entregar como infraestructura ya preparada; no es el objetivo principal del ejercicio.
  2. await Clerk.load(...) espera a que el servicio esté listo. await permite esperar dentro de una función async sin bloquear la página.
  3. addEventListener("click", ...) ejecuta la acción cuando el alumno pulsa un botón.
  4. Clerk.openSignUp() y Clerk.openSignIn() muestran los formularios. Clerk se encarga del proceso de registro y autenticación.
  5. await Clerk.user.createPasskey() inicia la creación de la credencial para el usuario conectado.
  6. Clerk.addListener(actualizarPantalla) mantiene la interfaz acorde con los cambios de sesión. textContent escribe el nombre como texto.
  7. try/catch/finally permite comunicar errores y reactivar el botón aunque la operación se cancele.

Carga de ClerkJS · Métodos del objeto Clerk.

Explicación oral sugerida: «El servicio envía un reto. El móvil pide permiso para usar una credencial y genera una respuesta firmada. Clerk la comprueba y crea la sesión. Nuestra página recibe información de esa sesión, nunca la huella».

La passkey es una credencial criptográfica; la huella es una forma de autorizar su uso. Algunas passkeys se sincronizan mediante el gestor del usuario, por lo que no deben describirse como necesariamente exclusivas de un único teléfono.

6. Comprobaciones y problemas frecuentes

  • Mensaje de configuración: comprueba los dos valores de config.js, guarda, vuelve a subirlo si procede y recarga.
  • No carga Clerk: comprueba que clave y dominio pertenecen a la misma instancia, que el dominio no incluye el protocolo y que la red no bloquea Clerk. Consulta la consola del navegador.
  • No aparece el acceso con passkey: verifica que está habilitado en esa instancia y que la cuenta tiene una passkey registrada. Conserva el acceso por correo.
  • El móvil pide PIN o rostro: es válido; depende del dispositivo, del gestor y de su configuración. La aplicación no selecciona la modalidad biométrica.
  • No se encuentra la credencial: comprueba dominio, cuenta, navegador y gestor utilizados al crearla. Evita probar en modo privado o en el navegador integrado de una app de mensajería.
  • Cancelación: cancela una creación y comprueba que puedes repetirla. Cancela también un acceso desde una sesión cerrada: no debe aparecer una sesión iniciada.
  • Dispositivo incompatible: utiliza el acceso por correo para seguir la práctica y observa la demostración de passkeys en otro dispositivo.

No hace falta crear una aplicación nativa Android, instalar Expo ni configurar una asociación con un paquete Android: este ejemplo es una web que se abre en el navegador.

7. Alcance y actividad final

La autenticación es real, pero el HTML es público. Cambiar hidden en el navegador permite ver las zonas de esta demostración: no hay notas, documentos privados ni operaciones protegidas. Para añadirlos, el servicio que entregue los datos deberá validar la sesión y los permisos. Un if en JavaScript no sustituye esa autorización.

Actividad: añade un texto de bienvenida personalizado y un botón para cambiar el color de la tarjeta, localizando los elementos con getElementById. Después responde: ¿quién verifica la credencial?, ¿recibe la web la huella?, ¿por qué se necesita HTTPS?, ¿por qué hay que cerrar sesión para repetir la prueba?

Entrega sugerida: los archivos y una breve descripción de las pruebas de registro, creación, cancelación y acceso. No entregues contraseñas, códigos de correo ni claves secretas.

Verificación del ejemplo: el código se entrega sin credenciales. La prueba completa con el servicio y con el sensor requiere configurar vuestra instancia y realizar el recorrido del apartado 4 en un móvil.
